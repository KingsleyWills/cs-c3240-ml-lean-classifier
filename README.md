# trustmebro

Predict the next Lean tactic family from the current proof state.
Stage 2 uses a custom Lean extractor; Stage 1 used LeanDojo v2.

## Stage 2 extraction

Requirements: [Pixi](https://pixi.sh/) and [Lean/Lake](https://lean-lang.org/install/) with the pinned toolchain.
Pixi manages Python and the native dependencies, including graph_tool, Graphviz, and Cairo.
The environment includes CUDA-enabled PyTorch and requires an NVIDIA driver supporting CUDA 12.9 or newer.
Run commands from the repository root.
No GitHub token is required.

Build the extractor and run the full Mathlib pipeline:

```sh
lake build trustmebro-extract-state
pixi run --locked trustmebro-build-dataset \
  --db data/mathlib.db --workers 3 --timing --sample-size 750 --seed 2
```

The pipeline discovers files, extracts a sample, trains compression dictionaries, and extracts the remaining files.
It then retrains the dictionaries and recompresses the full database.
Rerun the same command to resume; completed files are skipped.
Use a new database when changing selection or dictionary settings.
Databases and dictionary files using the previous field names must be regenerated; they are not migrated automatically.
Allow several GB of memory per Lean worker and for dictionary training.

The database contains extracted proof states, not model-ready features.
Exported expression graphs group applications/binders and apply lossy rules for registered coercion and arithmetic heads; they are not reconstructible typed Lean terms.
Use a fresh database and regenerate its downstream artifacts when changing these rules.
Compression dictionaries are embedded.
Candidate and sample lists and a CSV log are written beside the database.

For manual file selection:

```sh
pixi run --locked trustmebro-find-files --output data/candidate-files.txt
pixi run --locked trustmebro-sample-files --files-from data/candidate-files.txt \
  --count 750 --seed 2 --output data/sample.txt
pixi run --locked trustmebro-extract-proof-states \
  --files-from data/sample.txt --db data/sample.db --workers 3 --timing
```

File-list lines beginning with `#` are ignored.
Manual extraction also resumes from the database.
Use `trustmebro-train-dictionaries` for separate dictionary training and `--help` for command options.

## Partitioning and learning data

Supply a [label policy](doc/internal/corpus-partitioning.md) and split whole theorems into a development pool and held-out test data:

```sh
pixi run --locked trustmebro-partition-corpus --db data/mathlib.db \
  --labels doc/internal/labels.json --output data/split --test-frac 0.2 --seed 1 \
  --train-min-trns 100 --test-min-trns 20 --train-min-theorems 10 --test-min-theorems 5
```

This creates `train.db` and `test.db` in a new directory, preserving the compressed records and dictionaries.
The thresholds are examples, not adopted experiment settings; defaults guarantee label presence only.
Make the inner training/validation split before fitting a vocabulary, and reserve the outer test data for final evaluation.
The [Python API](doc/internal/corpus-partitioning.md#python-api) streams labeled transitions and sparse feature batches with a supplied vocabulary.

## Visualizations

Analyze once, then redraw without repeating the corpus analysis:
Use a completed, immutable database; concurrent extraction or recompression during analysis is unsupported.
The extractor now stores flattened application operands and grouped binders; create a fresh database and analysis directory instead of reusing binary-expression artifacts.

```sh
pixi run --locked trustmebro-analyze --db data/mathlib.db --stats data/analysis --workers 4
pixi run --locked trustmebro-graphs --stats data/analysis --output data/graphs
```

All graph families are generated by default.
Use `--list-graphs` to list families, or select them with `--graphs complexity reuse topology local-patterns`.
Use `--dot-diameter N` to adjust scatterplot dots.
The combined command runs only the analyses required by the selected families:

```sh
pixi run --locked trustmebro-graph-pipeline --db data/mathlib.db --stats data/analysis --output data/graphs --workers 4
```

Analysis supports `--analyses metrics topology patterns`, `--pattern-depths 1 2 3`, and `--limit N` for smoke tests.
Use `--analyses vocabulary` to archive label-neutral, position-preserving candidate observations for feature design.
See [vocabulary observations](doc/internal/vocabulary-observations.md) for their scope.
`--workers N` controls analysis processes and UMAP threads; `--skip-embedding` omits UMAP.
`--aggregation-memory-mib N` sets the spill threshold for buffered pattern counters, not a total-process memory limit.
Use `--timing-dir DIR` with a fresh directory for per-process wall-clock and CPU timing CSVs.
Use `--replace` to regenerate measurements; interrupted analyses restart rather than resume.
Replacements publish only after all requested analyses and embeddings succeed, leaving previous results usable on failure.
Analysis uses the exported graph as its baseline; Python application/binder-flattening comparisons were removed.
Optional instance/coercion views remain available through the structural graph families.
Regenerate existing measurements with `--replace` after this change; the new source database does not need another extraction.
Completed generations are retained under the measurements directory so active readers can finish safely.
Measurements are compressed MessagePack archives, not SQLite caches.
Graph rendering does not change them or access the source database.
UMAP coordinates are exploratory, not evidence of semantic clusters.

## Feature preparation

Build model-ready features from the outer training database (the development pool):

```sh
pixi run --locked trustmebro-prepare-features build \
  --db data/split/train.db --labels labels.json --output data/learning \
  --dims 1000000 --workers 10 --validation-frac 0.1 --seed 1
```

Candidates are extracted once before splitting.
Use `--candidates data/vocab-build/candidates.zst` to reuse a compatible archive of the complete development pool.
Replace `--validation-frac 0.1` with `--folds 3` for theorem-disjoint, label-stratified cross-validation.
Each instance fits coverage, supervised shapes, and names using only its training theorems, then converts the entire development pool once.
`--workers` also controls the supervised association, redundancy, and name-selection passes, with separate progress for each pass.
Shape enrichment balances supported positional node-kind count associations across tactic families, accounting for dimension cost and redundancy.
The build summary reports each family's strongest available and retained association; these are training statistics, not validation results.

Outputs are shared candidates plus `instance-01/`, etc., containing `split.json`, `vocab.zst`, `coverage.zst`, `features.zst`, and `feature-stats.zst`.
All models and hyperparameter settings can reuse the same instance.
Rerunning an unchanged command resumes completed stages; changed inputs/settings require a new output directory.
To use the revised selector, choose a new output directory and reuse the existing candidates; old vocabularies and vectors remain usable but are not automatically refitted.
The summary records stage durations, dimension budgets, activation counts, and compressed/uncompressed artifact sizes.

`--dims` caps the complete vector, including structural counts, attributes, statistics, ordered hypothesis slots, and selected names.
The default discovery depths are 1–5, with 32 hypothesis slots and 20% of the post-baseline budget reserved for names.
Label-support minima default to one transition and one theorem per family in each role; use the corresponding `--train-min-*` and `--validation-min-*` flags for stronger requirements.
Holdout assignment repairs violated minima; K-fold mode verifies its stratified assignment and fails if any fold lacks support.
Memory guards bound retained evidence/index buffers, not total process memory.

Load either logical portion without copying the database or rebuilding features:

```python
from pathlib import Path
from trustmebro.preprocessing.corpus import TrainingCfg, load_training_matrix, read_training_batches
from trustmebro.preprocessing.partition import read_split

root = Path("data/learning/instance-01")
split = read_split(root / "split.json")
cfg = TrainingCfg(dtype="float32")
for batch in read_training_batches(root / "features.zst", split=split, subset="train", cfg=cfg):
    X, y = batch.matrix, batch.label_ids

validation = load_training_matrix(root / "features.zst", split=split, subset="validation", cfg=cfg, max_bytes=4 * 2**30)
```

Loaders verify the manifest belongs to the feature archive; scaling, shuffling, and model fitting remain training responsibilities.
Streaming limits bound encoded frames, rows, and nonzeros per batch, not total RSS.
The full loader allocates the selected sparse matrix within its numeric-buffer budget.

Apply the final frozen vocabulary to the outer test database without fitting anything:

```sh
pixi run --locked trustmebro-prepare-features convert \
  --db data/split/test.db --vocab data/learning/instance-01/vocab.zst --labels labels.json \
  --output data/test-features.zst --stats data/test-feature-stats.zst --workers 10
```

Exploratory candidate extraction, inventory, coverage preparation, and structural selection commands remain available; see `--help`.
`trustmebro-select-vocabulary` selects unsupervised structural baselines; supervised fitting uses `trustmebro-prepare-features build`.
Render learning diagnostics with `trustmebro-graphs --graphs features --feature-stats … --output …`.
See [feature preparation](doc/internal/feature-preparation.md) for artifact reuse and [feature representation](doc/internal/feature-representation.md) for the channel definitions.
Encoded uncompressed sizes describe stored data, not decoded-object memory.

## Model training

Train one MLP with `pixi run --locked python src/trustmebro/mlp-pytorch/train.py --help`.
For an ordered list of experiments with shared defaults and resumable results, edit the [example plan](src/trustmebro/mlp-pytorch/example.json) and run:

```sh
pixi run --locked python src/trustmebro/mlp-pytorch/experiments.py \
  --config src/trustmebro/mlp-pytorch/example.json
```

See the [MLP instructions](src/trustmebro/mlp-pytorch/README.md) for settings and output files.
Train logistic regression with:

```sh
pixi run --locked trustmebro-train-logistic --instance data/learning/instance-01 --verbose
```
## Stage 1 tools

The Stage 1 tools are retained for reference and require a separate environment with LeanDojo v2 1.0.9 and tqdm.
These dependencies are not included in the current Pixi environment.
Provide an immutable 40-character Mathlib commit and a GitHub token with read-only public-repository access.
Set `GITHUB_ACCESS_TOKEN` in your environment; never store it in the repository.
Run `trustmebro-stage1-extract --commit COMMIT_HASH` in that environment.
Use `--summarize-existing` to refresh statistics or `--trace-root PATH` to reuse a raw trace.
`trustmebro-stage1-compat` runs the small compatibility experiment; see `--help` for options.
